## 2. Validation point par point de l'audit

### 2.1 Critique de C-003 — Budget d'actions

**Affirmation de l'audit** : *"Si l'agent répète une action inefficace, il consomme
davantage de ressources sans améliorer sa stratégie."*

**Confirmation MESURÉE** :

- sk48 actions 190-199 (log fin) : LuCY exécute ACTION1 en boucle avec `ps_rules=190+`
  et `stuck_streak=0`. Les `n_total` ACTION1 passent de 28 → 29 → 30 → 31 sur ces actions.
- `stuck_streak` ne se déclenche pas car `fp_prefix` change à chaque action
  (le frame change visuellement — GROWING — mais `levels_completed` reste 0).
- **Conclusion confirmée** : augmenter le budget de 200 → 500 prolongerait cette boucle
  ACTION1-dominante sans garantir de victoire.

**Correction de L-038 nécessaire** : L-038 §8 affirmait que 500 actions vaudraient
la peine *avant* C-006/C-007. L'audit a raison de nuancer : sans correction stratégique,
500 actions reproduit probablement le même `BUDGET_EXHAUSTED, levels=0`.

### 2.2 Critique de C-004 — Diagnostic r11l

**Affirmation de l'audit** : *"Cette estimation ne peut pas être considérée comme un
budget minimal validé sans connaître la condition de victoire."*

**Confirmation ÉTAYÉE** :

Le log `lucy_C005_r11l_500steps_20261015T221124Z.log` est disponible dans les logs
(session L-036/L-037) mais n'a pas été relu dans cette session. Ce qui est connu de
L-036 : r11l rapportait une variation nette de +3 pixels/action, classé GROWING.
Ceci est cohérent avec sk48 (également GROWING) où 199 actions n'ont produit aucun
`level_up` malgré un score `visual_delta` élevé.

**Recommandation confirmée** : tester r11l à 500 actions *après* C-006 + C-009,
pas avant. Métrique à surveiller : transition `GROWING → WINNING` ou `levels_completed > 0`.

### 2.3 Critique Défaut B — Détection d'animation

**Affirmation de l'audit** : *"Seuil 50ms non validé — suggestion : détecter la
stabilité d'état, pas juste le temps écoulé."*

**Évaluation ÉTAYÉE** :

sb26 log : `elapsed_ms=27 087ms` pour 199 actions = 136ms/action. Mais le seuil
brut de 136ms *moyen* masque une distribution non uniforme : certaines actions
peuvent être quasi-instantanées (jeu stable) tandis que d'autres déclenchent des
animations de 500ms+.

Le critère `elapsed_ms / n_actions > 50ms` de L-038 est un proxy proxy grossier.
L'audit a raison :

| Critère | Avantage | Limite |
|---------|----------|--------|
| `elapsed_ms / n_actions > seuil` | Simple, sans état | Sensible aux outliers ; faux positif si une seule action est lente |
| Stabilité de `fp_prefix` | Détecte l'état réel du frame | Requiert 2 frames consécutifs identiques |
| `changed_frac == 0.0` sur 2+ tours | Direct, sans timing | Le jeu peut être stable sans animation (ex. : action sans effet) |

**Décision pour C-006** : implémenter la **stabilité de frame** (`fp_prefix` identique
sur N=2 appels consécutifs) comme critère principal, avec le timing comme signal
de secours. Pas de valeur hardcodée.

### 2.4 Critique Défaut C — `_GoalDeltaTracker`

**Affirmation de l'audit** : *"Distinguer : attrs mal nommés vs interface non exposée
vs logique incorrecte."*

**Évaluation ÉTAYÉE** :

Log sk48 ligne 12 : `"goal_attr_used":"NOT_FOUND"`. Cela signifie que
`_GoalDeltaTracker` n'a trouvé aucun attribut dans `_GOAL_ATTRS` correspondant
aux attributs du `GameState` sk48.

Trois causes possibles (non encore discriminées sans lecture du code source
`_GoalDeltaTracker`) :

1. **HYPOTHÈSE A** (attrs mal nommés) : sk48 expose `lgdrixfno` mais `_GOAL_ATTRS`
   cherche des noms génériques (`score`, `progress`, `completion`, etc.)
2. **HYPOTHÈSE B** (interface non exposée) : l'attribut de victoire de sk48 n'est
   pas dans le `GameState` observable par l'agent
3. **HYPOTHÈSE C** (logique incorrecte) : l'algorithme de matching tente une
   comparaison de type qui échoue silencieusement

**Action pour C-009** : lire le code de `_GoalDeltaTracker` dans `my_agent.py`
ligne par ligne, puis inspecter les `GameState` de sk48/tr87/sb26 pour identifier
lesquels de A/B/C s'appliquent.

### 2.5 Critique Défaut D — Phase EXPLOIT prématurée

**Affirmation de l'audit** : *"Défaut de politique — changement visuel ne justifie
pas l'exploitation prolongée."*

**Confirmation MESURÉE** :

Log sk48 seq=26 : `action_count=7`, `phase=exploit`, `visual_delta=0.0249`.
→ Transition `explore → exploit` à l'action 7 avec seulement 6 observations.
→ `n_progress_real={}` à ce stade (aucune progression réelle).

Le `_CognitiveEngine` est configuré avec `EXPLOIT_THRESHOLD` (non lu dans cette
session) qui déclenche l'exploitation sur la base de `visual_delta` accumulé,
sans vérifier `real_progress > 0`. C'est un **défaut de politique confirmé**.

**Impact mesuré** : de l'action 7 à l'action 199 (= 192 actions), LuCY est en
phase `exploit` en boucle avec `levels_completed=0` constant.

## 5. Spécification C-006 — Stabilisation cycle action-observation

### 5.1 Objectif

Attendre que le frame soit stable avant d'envoyer l'action suivante.
Éviter d'envoyer des actions pendant une animation en cours.

### 5.2 Critère de stabilité (révisé selon audit)

**Critère principal** : `fp_prefix` identique sur 2 appels consécutifs
(`frame_before_action == frame_after_prev_action`)

**Critère secondaire** : `changed_frac == 0.0` sur l'action précédente (signal direct)

**Critère de secours** : timing `elapsed_ns` de l'action > seuil adaptatif
(basé sur la médiane des actions précédentes × facteur 3)

| sk48 | ~18ms | 50ms | Actions rapides, animations courtes |
| tr87 | ~13ms | 50ms | Actions rapides |
| sb26 | ~136ms | 200ms | Animations longues, seuil dynamique |

### 5.4 Critère de validation C-006

**Après** : sb26 `n_visual_change` total > 5 sur le même nombre d'actions

## 10. Décision architecturale — Autonomie avec contrôle

L'audit formule le principe : *"liberté d'exploration, vérification systématique
des résultats et adaptation automatique à partir de preuves mesurables."*

**Application à LuCY v12.1** :

| Mécanisme | État actuel | Manquant |
|-----------|-------------|----------|
| Détection de blocage | `stuck_streak` (seuil=8) | Seuil trop haut ; `fp_prefix` répété non détecté |
| Vérification des résultats | `n_progress_real` / `real_level_ups` | Ne mesure pas la progression interne au niveau |
| Gestion des ressources | Budget respecté | Budget sans adaptation au signal qualitatif |
| Retour sur stratégie inefficace | Phase RECOVER (RESET) | Reset sans stratégie alternative = boucle |
| Détection d'animation | Absent | → C-006 |
| Contrat de victoire | `_GoalDeltaTracker` silencieux | → C-009 |
| Sondage systématique | Absent | → C-007 |
