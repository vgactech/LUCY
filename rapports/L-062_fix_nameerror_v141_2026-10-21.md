## 2. Analyse forensic du bug F-023

### 2.1 Chronologie du renommage

| Version | Événement |
|---------|-----------|
| v13.0 | `_validate_transposition(frame)` existe — prend un frame en paramètre |
| v13.1 | Renommé en `_validate_transposition_regression()` (sans paramètre) + création de `_validate_live_frame(frame)` pour la validation réelle |
| v14.0 | FIX-HOT-F021 réécrit la doc et le module-level, mais **l'appel ligne 2279 n'a pas été mis à jour** |

### 2.2 Localisation exacte

**AVANT (v14.0) — Fichier : `LuCY/agent/my_agent_v140.py` — Ligne 2279 :**
```python
tv = _validate_transposition(latest_frame.frame)
# → NameError: name '_validate_transposition' is not defined
```

**APRÈS (v14.1) — Fichier : `LuCY/agent/my_agent_v141.py` — Ligne 2289 :**
```python
lv = _validate_live_frame(latest_frame.frame)
# + mapping des champs {ok, errors, rows, cols, format} vers {ok, passed, failed, details}
```

### 2.3 Pourquoi `_validate_live_frame` et pas `_validate_transposition_regression`

| Fonction | Paramètre | Usage |
|----------|-----------|-------|
| `_validate_transposition_regression()` | aucun | Tests synthétiques internes — vérifie la logique de transposition sur des grilles artificielles |
| `_validate_live_frame(frame)` | le frame réel | Valide la capture courante du moteur de jeu — c'est ce qu'on veut ici |

La ligne 2279 reçoit `latest_frame.frame` (frame réel) → `_validate_live_frame` est la fonction correcte.
